# Motion Studio: studio-grade motion design in code

This skill turns a request ("animate my logo", "make a sting", "transition for the lesson", "app promo", "animated post with numbers") into a finished video: **HTML/SVG/Canvas with a deterministic `render(t)` → Chromium captures frame by frame → motion blur from subframes → ffmpeg (H.264 BT.709 + AAC) → a synthesized soundtrack synced event by event.** Default delivery: **16:9 (1920×1080) and 9:16 (1080×1920)**, 30 fps, with sound.

The skill is **neutral**: it starts from no fixed visual identity. Colors and fonts always come from the project's brand or from an art direction chosen for it (section 3). The user's personal identity only enters when the project is their own brand.

**Language:** write on-screen text in the language of the user's request or brand (check spelling and accents for that language), and talk to the user in their language. The reference files in `references/` are in English.

## 1. Workflow

1. **Brief (quick).** From the request take: goal, where it will run (Reels, YouTube, lesson, site, presentation), duration, **exact text**, brand (SVG logo, colors, fonts), sound mood. If the text or the brand is missing and cannot be deduced, ask once. Decide the rest with good taste and say what you decided. **A vague request ("make a cool video", "showreel", "app promo") does not go straight to code:** build the 6-block brief (section 11) from the closest template in `references/briefing-templates.md`, with a one-line concept, and show the user the concept, the palette, what is banned and the beat map.
2. **Art direction.** The client's brand or a preset (section 3). Define the tokens at the top of the scene.
3. **Beat map.** Write (for yourself) a table `time → what happens → sound cue → blur`, following the format's structure (section 6). Think of **one central idea**, stated in one line, and a **bridge element** that links the scenes (a shape, a color, a character). With music or a defined rhythm, count in **BPM and bars** (`bpm` in `M.boot`, `M.beat(n)`), with something happening on every strong beat, not in "dynamic".
4. **Scene.** Copy `template.html` → `scene.html`. Create elements once; in `render(t)` only update properties. Horizontal and vertical layout with `M.pick(h, v)` and the safe areas `M.safe`. Measure texts in `init()` (after fonts load).
5. **Contact sheet.** `node render.mjs scene.html --stills 12 --sizes 1920x1080,1080x1920` and **look at both images** (Read). Fix composition, cropping, legibility, contrast and safe areas before any video. For beat-based pieces, take **one frame per beat** (`--stills` with the beat times) and fix anything off the grid, cramped, overlapping or illegible.
6. **Determinism.** `node render.mjs scene.html --check` must report "idêntico" (identical) everywhere.
7. **Draft (optional, for rhythm).** `node render.mjs scene.html --draft` (half resolution, no blur, fast).
8. **Sound.** `node render.mjs scene.html --cues cues.json` → `python3 sound.py cues.json track.wav --mood grave`.
9. **Final render.** `node render.mjs scene.html --name Project_Name --sizes 1920x1080,1080x1920 --audio track.wav --outdir out`
10. **QA** (section 9), then **deliver**: save the files in the user's project folder (on their computer, if connected), send the videos and say in 1 or 2 sentences what was done. Offer the most likely tweaks (text, timing, color, sound).

For a change request: edit only what changed in the scene, redo the contact sheet for that stretch (`--stills 3.2,3.6,4.0`) and render again. Do not rewrite the scene from scratch.

## 2. Golden rules (technical)

- **`render(t)` is a pure function of time.** Forbidden inside render: `requestAnimationFrame`, `setTimeout`, `Date`, `performance.now`, `Math.random`, CSS `transition`/`animation`, state accumulated between frames. Randomness only through `M.rng(seed)` / `M.hash(i, j, seed)` / `M.noise2`. Simulation (particles with physics) = **precompute in `init()`** and index by `t`.
- **Everything is created once and updated in render.** Do not rebuild the DOM per frame.
- **Local fonts** via `fonts.mjs` (Google Fonts → `fonts/fonts.css`). No system fonts as the main font.
- **Sound cues and `M.blur` are registered at setup** (outside render), with the same times as the actions.
- **Text whose value changes** (counter, typing, scramble, timecode, percentage) uses `M.frameT(t)` (time at the center of the frame). Without it, motion blur mixes two values and a ghost digit appears.
- **Scale:** use `u(x) = x * M.S` (M.S = shorter side / 1080) for every size. That way the same scene serves 16:9, 9:16, 1:1 and 4:5.
- **Fast motion = more blur samples:** mark with `M.blur(t0, t1, 6)` (moderate) or `12` (whip, iris, fast morph, fly-through). Otherwise the default is 4, and still frames are detected automatically.
- **No heavy full-screen effects** (mix-blend-mode, backdrop-filter, large filter: blur) over the whole scene. Each costs tens of ms per frame. Use them sparingly.
- **Images:** local `<img>`/SVG in `assets/`. Video inside the scene is not deterministic: extract frames with ffmpeg and swap `src` by index (`Math.floor(t*fps)`), or composite later with ffmpeg overlay.
- **WebGL/Three.js:** `--gl`, `preserveDrawingBuffer: true`, and call `renderer.render()` inside `render(t)`.

## 3. Art direction (always from the project)

**Procedure:**
1. The client has a brand → use theirs (SVG logo, colors, fonts). Proprietary font unavailable → ask for the file or use the closest Google Fonts equivalent and say which.
2. No brand → pick the preset by tone and audience. Adjust 1 accent color to the segment if it makes sense.
3. Tokens: `bg, surface, ink, muted, accent, accent2`. 60/30/10 proportion (background/support/accent). Text contrast ≥ 4.5:1 (`M.contrast(a, b)`).
4. Typography: at most 2 families + 1 optional mono. Display at high weight with negative tracking (−2% to −5%); emphasis in italic serif or in the accent color, never both.
5. The background is never "dead": subtle grid, gradient, texture, light grain or large blurred shapes.
6. Composition: one focal point per frame, lots of negative space, alignment on a grid (12 columns in 16:9, 6 in 9:16), thirds for supporting elements. Never touch the edge with text.
7. Polished text: `font-kerning: normal`, correct quotes and dashes, tabular numbers in counters, no single word on the last line of a title.

## 4. Timing, easing and choreography

**Durations (30 fps):**
- Micro (click, hover, tap): 80 to 150 ms (3 to 5 frames)
- Small element entering: 300 to 500 ms
- Title or large element: 500 to 900 ms
- Transition between scenes: 300 to 600 ms (whip pan: 250 to 350 ms)
- Reading hold: 0.3 s + 0.25 s per word (minimum 1 s for a title)
- Final still logo: ≥ 1.2 s (sting is ≥ 0.6 s)

**Curves (`M.ease`, `M.curve`, `M.spring`):**
- **Enter:** decelerate → `outExpo`, `outQuint`, `M.curve.snappy` (premium motion signature)
- **Exit:** accelerate and be shorter than the entrance (≈70%) → `inCubic`, `inExpo`, `M.curve.accel`
- **Move within the screen:** `inOutCubic`, `M.curve.standard`. Large displacement or zoom: `inOutExpo`
- **Personality:** `outBack(p, 1.2–2)` for playful; `M.springAt(t, t0, 'bouncy'|'snappy'|'gentle'|'wobbly')` for organic; `inOutSine` for luxury and calm
- **Scale/zoom:** interpolate with `M.expLerp` (constant perceived speed); "zoom through" = exponential scale until it covers (`M.cover`)
- Never use `linear` on position; only on continuous rotation, tickers and time counters.

**Choreography:**
- **Stagger:** letters 20 to 40 ms · words 60 to 120 ms · cards/items 50 to 90 ms · grid by distance 20 to 40 ms (`M.stagger`, `M.staggerGrid`)
- **Overlap:** the next action starts when the previous one is at 60 to 80%. Never wait for everything to stop.
- **Anticipation:** 3 to 6 frames pulling back 5 to 10% before a big move (`M.curve.anticipate`)
- **Follow-through:** secondary parts arrive later and settle (small overshoot)
- **Hierarchy:** one focus at a time; secondary motion is smaller and slower
- **Arcs:** objects and cursors travel on curves (`M.arc`, `M.cursorPath`), not straight lines
- **Life:** nothing is 100% still. Use subtle drift (`M.drift`), a 2 to 4% push-in across the shot, a breathing glow
- **Rhythm:** vary it (short, short, long). With fixed-BPM music, align the beats (`M.beat(n)`)
- **Scale contrast:** alternate wide shots and details; change the background color every scene in a reel
- **Opacity alone is weak:** combine with displacement, scale, mask or blur

## 5. Technique library (the best ones, with recipes)

Each item: **what it is** → how to do it with the kit. Combine 3 to 6 per piece; do not use everything.

**A. Kinetic typography**
1. **Rise from inside a mask** (the strongest). `M.split(el, {mask:'lines'|'words'})`; animate `.in` from `y: 100%` → 0 with `outExpo` 0.6 to 0.8 s and 60 to 90 ms stagger; exit continues upward with `inCubic`.
2. **Letter cascade.** `split().chars`, y +40%, rotation 6 to 10°, `outExpo`/`outBack(1.4)`, 25 to 35 ms stagger.
3. **Decoding (scramble).** `M.scramble(text, p, {tick: Math.floor(t*20)})`: random glyphs resolve left to right. Pairs with tech and HUD.
4. **Human typing.** `M.typewriter(text, M.frameT(t), t0)` → `{text, caret}`, irregular rhythm and a pause on punctuation. Cue `type`.
5. **Weight mixing.** Black sans + italic serif on the emphasis word (accent color) + an underline that draws itself (`M.draw`).
6. **Word swap (slot).** Words stacked in a one-line mask; swap with `inOutExpo` and a slight overshoot.
7. **Counter.** `M.fmt(value, {prefix:'+', suffix:'%'})` with `outExpo` over 1 to 1.5 s, computed with `M.frameT(t)`; `font-variant-numeric: tabular-nums`.
8. **Marquee ticker.** Diagonal strips, `x = (t*speed) % patternWidth`; seamless loop.
9. **Variable tracking/weight.** Variable font: animate `font-variation-settings: 'wght'` and `letter-spacing` (−0.05em → 0.3em).
10. **Giant type + camera.** Text bigger than the frame, cropped, with a slow push-in and an offset outline (stroke) copy in parallax.
11. **Handwritten annotations.** Circles and arrows with a wobble (`M.noise2` on the radius), drawn with `M.draw`, one at a time.

**B. Logo**
12. **Geometric construction** (grid → strokes → fill). Guides draw from the center, dashed circles with `M.draw`, stroke arcs, switch to the fill with a flash or ring; slight pop (`1 + 0.07·sin`).
13. **Particles forming the mark.** `M.sampleShape({d})` or `({text, font})` in `init()`; particles leave seeded positions with noise drift and converge with `inOutCubic` and individual delay; the solid shape enters on impact (cue `big`).
14. **Assembly by parts.** Each part enters from a different offset/rotation, `outExpo` + stagger; the last piece "locks" with a spring.
15. **Morph from a primitive to the logo.** `M.morpher(dCircle, dLogo)` → `f(p)` returns the intermediate `d` (one closed shape at a time).
16. **Mask/wipe reveal.** A rectangle or brand shape sweeping; `clip-path` in HTML or `<mask>` in SVG.
17. **Lockup.** The icon is born centered and slides (`inOutExpo`) to make room; the name rises from the mask.
18. **Sweeping shine.** A slanted gradient strip passing over the lockup (mask/soft-light), 0.6 to 0.8 s.
19. **Sting (1 s).** A single gesture: dot falls → squash → logo pop (spring). Cues `pop` + `hit`.

**C. Transitions**
20. **Shape wipe (layered iris).** 2 to 3 shapes (color A, color B, next scene background) growing from a point with 60 to 120 ms between them; radius with `M.expLerp` up to `M.cover`.
21. **Zoom through.** Exponential scale into a "hole" (the logo's counter-shape, the letter O, a phone screen) and the next scene appears inside.
22. **Whip pan.** The whole world slides one screen in 8 to 10 frames (`M.curve.swift`) + directional blur proportional to speed (SVG filter `feGaussianBlur stdDeviation="X 0"`) + `M.blur(...,12)`.
23. **Blinds/strips.** 8 to 12 strips with `scaleY` and 20 to 30 ms stagger.
24. **Match cut / object morph.** The element from scene A becomes the one in scene B (button → circle → planet). This is the "bridge element".
25. **Cut with flash/light.** A radial light peak (screen) of 3 to 5 frames exactly on the cut.
26. **Glitch.** 3 to 5 frames: displaced horizontal slices + RGB split (copies with `mix-blend-mode: screen` in R/G/B).
27. **3D cards.** `perspective` + `rotateY` (flip) or cards flying with depth and different rotations.
28. **Blob/ink (gooey).** Circles with SVG filter `feGaussianBlur` + `feColorMatrix` (alpha 18 −7) merging.

**D. Product UI**
29. **Choreographed cursor.** `M.cursor()` + `M.cursorPath(t, keys)` on arcs; click = scale 0.85 over 3 frames + ring (`ripple`). Cue `click`.
30. **State morph.** Button → loader → ✓ → card, without cuts: width/height/radius interpolated and color with `M.mix` (OKLab).
31. **AI flow.** Prompt box typing → send → collapse into a dot → result assembling.
32. **Floating mockup.** Tilted phone/laptop (perspective) with content scrolling inside, shadow and sinusoidal float.
33. **Bento/dashboard.** Cards enter in a grid with distance-based stagger; numbers count; bars grow.
34. **Stacking notifications.** Toasts enter with a spring and push the previous ones.

**E. Data**
35. **Bars + line + dot.** Bars grow with `outExpo` stagger; the line draws on top (`M.draw`); the final dot enters with `outBack` and a pulsing ring; the hero number counts.
36. **Donut/pie.** `stroke-dasharray` on a circle by slice, one at a time.
37. **Map/route.** Path drawing + a marker moving along the path (`getPointAtLength`).

**F. Generative and particles**
38. **Flow field.** Particles following `M.curl(x, y, t)` (precompute trajectories in `init` if integrated).
39. **Grid/isometric wave.** `h = f(sin(dist − t·speed))`; tiles lift along the diagonal (`M.staggerGrid`).
40. **Orbits.** Satellites on ellipses with depth sorting (scale and opacity by z).
41. **Ray burst.** Conic rays slowly rotating behind the hero + outgoing particles.
42. **Icon wall.** A large grid revealed radially from the center, with one highlighted icon.

**G. Camera and depth**
43. **2.5D parallax.** Layers with `M.depth(z)`; camera `M.cam({x, y, zoom, r})` on the world group.
44. **Impact shake.** `M.shake(t, t0, {amp: u(8–20), dur: 0.3})` only on the hit frame.
45. **Fake depth of field.** Distant layers with static `filter: blur()` (not animated full-screen).

**H. Character**
46. **Ball character.** Squash & stretch on contact (constant volume: `sx = 1/sy`), anticipation before the jump, eyes looking in the direction of motion, short trail. It is the best bridge element for a reel.

**H2. Techniques from the 230-prompt gallery (use 1 or 2 as the central idea, not all)**
48. **One shape that never cuts.** A single element becomes every state (button → loader → check → player → slider → toggle → tab → chart → ⌘K → toast → button): width, height, radius and color interpolated, content swaps with a short blur, the cursor performs real clicks and drags, last frame = first. See recipe C in `briefing-templates.md`.
49. **Continuous take.** "Nothing fades, blurs or cuts": text rises from a mask line, icons are born from zero on a spring, a dark shape floods the frame and contracts into the next scene. Screen Studio-style camera: zoom until each moment fills the frame, and the cursor scales with it.
50. **The "drop".** On the music's strong beat, an accent-color circle grows from an object (button, wok, dot) and floods the screen in ~0.35 s, swapping the scene. Cue `big` on the same frame.
51. **Liquid glass.** Background blur behind the control + bending the scene at the edge like thick glass + top sheen + bright rim + elevation shadow. On a white background glass disappears: put a slow pastel aura behind it.
52. **"Apple Intelligence" aura.** A blurred conic gradient rotating through pink, orange, lime, cyan and violet around the input field.
53. **Halftone.** A dot grid whose radius responds to an object (or its distance); it grows past the edges and reveals the final card.
54. **Word that transforms letter by letter.** Each letter animates on its own (`split().chars`) so "Reduce Motion" becomes "Motion", with the dot stuck to the "i" until it jumps; orbiting words that open into a dot field.
55. **Type with a physical role.** Each key word becomes a lintel, cable, support, opening or platform, born from the actual letterforms (vector deformation of the baseline), and the final sentence stands on what was built.
56. **A camera that never cuts on a still frame.** Each shot enters already moving (exponential ease-out, ~12 to 19% of the remaining distance per frame) and exits accelerating or on a blur ramp; one camera move per scene, no zoom in and out back to back.
57. **A cursor with intent.** Turns to face where it is going, grows on hover, sinks on click (0.85), ripple ring, cue `click`.
58. **Two edges, two springs.** Tab indicator and toggle knob with edges on different springs: the leading edge stretches ahead of the trailing one (liquid). A value that changes target many times = a sum of one spring per change, still a pure function of time.

**I. Finishing**
59. **Grain** (`M.grain`, default 2%, swaps 8×/s) against banding in gradients and for texture. Noise does not compress: heavy grain multiplies file size (measured: from 0.3 MB to 8 MB in 3 s), so keep it light, or heavy only for a cinema look · soft **vignette** (`M.vignette`, 0.1 to 0.3) · **glow** = blurred copy behind · **HUD** (corners, real timecode, mono labels) · **letterbox** · **motion blur** always.

### Code recipes (tested; copy and adapt)

```js
// 1. Rise from inside the mask — init: S = M.split(title, {mask:'lines'})
S.lines.forEach((ln, i) => {
  const q = E.outExpo(M.seg(t, 0.2 + i * 0.08, 0.9 + i * 0.08)), o = E.inCubic(M.seg(t, 2.2 + i * 0.05, 2.55 + i * 0.05));
  M.css(ln.in, { transform: { y: (1 - q) * ln.offsetHeight * 1.1 - o * ln.offsetHeight * 1.2 } });
});

// 2. Layered iris from (px,py) — 3 <circle> in different colors; setup: M.blur(t0, t0+0.6, 12)
[irA, irB, irC].forEach((c, i) => { const p = E.inOutCubic(M.seg(t, t0 + i * 0.1, t0 + 0.35 + i * 0.1));
  M.attr(c, { cx: px, cy: py, r: p > 0 ? M.expLerp(4, M.cover(1, px, py) * 1.02, p) : 0 }); });

// 3. Whip pan with directional blur — setup: <filter id="hb"><feGaussianBlur id="hbg" stdDeviation="0 0"/></filter>
const sw = x => M.curve.swift(M.seg(x, t0, t0 + 0.32)), p = sw(t), vel = Math.abs(sw(t + 0.01) - sw(t - 0.01)) / 0.02;
M.css(sceneA, { transform: { x: -W * p }, filter: vel > 0.2 ? 'url(#hb)' : 'none' });
M.css(sceneB, { transform: { x: W * (1 - p) }, filter: vel > 0.2 ? 'url(#hb)' : 'none' });
hbg.setAttribute('stdDeviation', `${Math.min(u(70), vel * u(9))} 0`);

// 4. Particles forming the mark (canvas) — init: pts = M.sampleShape({d: LOGO}, 600); starting positions with M.rng
for (const o of PTS) { const q = E.inOutCubic(M.seg(t, 1.0 + o.d, 1.9 + o.d)), n = M.curl(o.sx * 0.002, o.sy * 0.002, t * 0.3);
  ctx.fillStyle = o.c; ctx.beginPath();
  ctx.arc(M.lerp(o.sx + n[0] * u(60) * (1 - q), ox + o.p[0] * k, q), M.lerp(o.sy + n[1] * u(60) * (1 - q), oy + o.p[1] * k, q), u(3), 0, 6.283); ctx.fill(); }

// 5. Arc cursor + click — setup: cur = M.cursor(layer, {size: u(44)}); M.cue(1.65, 'click')
const cp = M.cursorPath(t, [[1.0, [W + u(60), H + u(80)]], [1.6, button], [1.75, button], [2.3, [W * 0.9, H * 1.1]]]);
M.css(cur, { transform: { x: cp[0], y: cp[1], s: 1 - 0.15 * M.pulse(t, 1.65, 0.07) } });

// 6. UI morph: button -> circle -> card
const col = E.inOutExpo(M.seg(t, 2.0, 2.4)), ex = E.inOutExpo(M.seg(t, 2.9, 3.3));
const bw = M.lerp(M.lerp(BTN.w, BTN.h, col), CARD.w, ex), bh = M.lerp(BTN.h, CARD.h, ex);
M.css(box, { width: bw + 'px', height: bh + 'px', left: (cx - bw / 2) + 'px', top: (cy - bh / 2) + 'px', borderRadius: M.lerp(bh / 2, u(24), ex) + 'px', background: M.mix(C.surface, C.accent, col * (1 - ex)) });

// 7. Hero number + bars + line
num.textContent = M.fmt(248 * E.outExpo(M.seg(M.frameT(t), 0.3, 1.6)), { prefix: '+', suffix: '%' });   // frameT: no ghost digit
bars.forEach((b, i) => { const q = E.outExpo(M.seg(t, 0.3 + i * 0.09, 1.0 + i * 0.09)); M.attr(b, { y: base - alt[i] * q, height: alt[i] * q }); });
M.draw(line, E.inOutCubic(M.seg(t, 0.9, 1.5)));

// 8. Impact: shake + pop + ring — setup: M.cue(tHit, 'big')
const sk = M.shake(t, tHit, { amp: u(10), dur: 0.3 }), pop = 1 + 0.08 * Math.sin(Math.PI * M.seg(t, tHit, tHit + 0.3));
group.setAttribute('transform', `translate(${x + sk.x} ${y + sk.y}) rotate(${sk.r}) scale(${k * pop})`);
const rr = M.seg(t, tHit, tHit + 0.6); M.attr(ring, { r: u(120) + u(320) * E.outExpo(rr), opacity: rr > 0 && rr < 1 ? 1 - rr : 0 });

// 9. Ball with squash & stretch (transform-origin: 50% 100%)
const pj = M.seg(t, t0, t0 + 0.6), contact = M.pulse(t, t0 + 0.6, 0.08), sy = 1 - 0.35 * contact + 0.15 * Math.abs(Math.cos(Math.PI * pj)) * (1 - contact);
M.css(ball, { transform: { x: M.lerp(xA, xB, pj), y: floor - Math.sin(Math.PI * pj) * height, sx: 1 / sy, sy } });

// 10. HUD-style decoding
const ft = M.frameT(t); title.textContent = M.scramble('SYSTEM ONLINE', M.seg(ft, 1, 2.2), { tick: Math.floor(ft * 20) });
```

## 6. Structures by format

- **Sting / logo reveal (3 to 10 s):** hook at 0.5 s (live background + first element) → build (1.5 to 3 s) → reveal (hit + flash/ring) → lockup + hold ≥ 1.2 s → optional exit. Also make the **short version** (1 to 3 s sting) reusing the same scene with remapped time: a URL flag such as `?curta=1` read with `M.Q` and, in render, `t = M.remap(t, [[0,0.55],[0.5,1.95],[1,3.35],[2.25,6.62],[3,9.5]])` (accelerated stretches, key moments preserved). Cues and `DUR` of the short version are remapped too.
- **Transition (0.6 to 1.7 s):** cover → swap → uncover. Offer the transparent overlay version (`--alpha`).
- **Lesson/video opener (5 to 8 s):** context (prompt/screen/tool) → kinetic title → signature or episode.
- **Showreel / manifesto (15 to 30 s):** 5 to 8 scenes of 2 to 4 s, a bridge element running through everything, background change every scene, cuts on the rhythm, ending with logo + CTA.
- **Product/app promo (15 to 30 s):** pain (2 s) → product in the mockup → 3 benefits with micro-UI (2 to 3 s each) → proof (number) → CTA.
- **Data post (6 to 10 s):** hero number + chart + caption; closes in a loop.
- **Loop (4 to 8 s):** final state equal to the initial one; compare first and last frame (`--stills 0,<DUR − 0.033>`).
- **Lower third / caption (3 to 5 s, alpha):** bar enters, name rises from the mask, exits in reverse order.

## 7. Sound

- The soundtrack is born from the scene's **cues**: `M.cue(t, type, {...})` at the same time as the visual action. Types: `hit`, `big`, `rise {len}`, `whoosh {len}`, `pop`, `tick`, `click`, `type {len, rate}`, `notes {notes, step}`, `pulse {n, every}`, `swell {len}`, `end`, `chord`.
- `sound.py` moods: **`grave`** (default: cinematic in D minor, warm pad, soft piano, deep impacts, filter risers, **no highs and no wind sound**), `epico`, `tech`, `clean`, `ambient`, `pop`. Key: `--key`.
- Rules: impact exactly on the reveal frame; the riser ends at the hit; typing with `type`; no sound on every micro-movement (choose the moments).
- Final loudness: `render.mjs` normalizes in 2 passes to **−14 LUFS** and true peak −1.5 dBTP (`--lufs` changes it).
- User's or stock music: pass the file in `--audio`; align the hits to the music's times (BPM → `M.beat`).
- No sound requested → generate a version with a soundtrack anyway and mention it can be removed.

## 8. Render, formats and delivery

```bash
node render.mjs scene.html --stills 12 --sizes 1920x1080,1080x1920      # contact sheet
node render.mjs scene.html --check                                       # determinism
node render.mjs scene.html --draft                                       # quick draft
node render.mjs scene.html --cues cues.json && python3 sound.py cues.json track.wav --mood grave
node render.mjs scene.html --name Client_Sting --sizes 1920x1080,1080x1920 --audio track.wav --outdir out
node render.mjs overlay.html --alpha --name Client_Transition --sizes 1920x1080,1080x1920   # ProRes 4444 .mov + .webm + _GREEN.mp4
```
- Sizes: 16:9 `1920x1080` · 9:16 `1080x1920` · 1:1 `1080x1080` · 4:5 `1080x1350` · 4K `3840x2160` (or `--ss 2` for supersampling).
- Name: `Name_16x9_1920x1080.mp4` (automatic with `--name`).
- Output: H.264 High, yuv420p, **BT.709 tagged** (same colors in every player), CRF 17, AAC 320k 48 kHz, faststart.
- Useful options: `--fps 60` (very fluid UI), `--sub 6` (more blur everywhere), `--workers N`, `--from/--to` (a stretch), `--crf 20` (smaller file), `--grain 4` (ffmpeg grain; greatly increases file size, only for cinema deliveries), `--params "text=Hello"` (URL variables for the scene → `M.Q.get('text')`).
- **Speed:** iterate with `--stills` and `--draft`; final render only at the end. Reference: ~1.5 frames/s with 2 cores and blur on; scales almost linearly with `--workers` (on a Mac, cores − 1). Each stretch with `M.blur(...,12)` costs 3× more.
- **Batch of variations** (same scene, different texts): read `M.Q.get('title')` in the scene and loop: `for t in "Lesson 1" "Lesson 2"; do node render.mjs scene.html --params "title=$t" --name "Transition_${t// /}" ...; done`.

## 10. Common problems

| Symptom | Cause → fix |
|---|---|
| Wrong font in the video | font not local → `fonts.mjs` + `<link href="fonts/fonts.css">`; measurements only in `init()` |
| `--check` differs | state between frames / clock / `Math.random` → pure function, precompute in `init`, `M.rng` |
| "Ghost" copies in fast motion | too few samples → `M.blur(t0, t1, 12)` on the stretch |
| Ghost digit/letter in a counter or typing | text computed with `t` → use `M.frameT(t)` |
| Banding in gradients | 8 bits → light `M.grain` or a gradient with more stops |
| Huge file | heavy grain/noise over the full screen → 2% grain (default) or `--crf 20` |
| Very slow render | heavy full-screen effect, PNG, huge scene → avoid continuous blend/backdrop-filter; JPEG (default); `--workers`; iterate with `--draft` |
| Element flickers between planes | two planes visible/hidden on the same frame → overlap with `M.on(t, plane, pad)` |
| Text wraps differently in 9:16 | fixed width → `M.pick` with per-format sizes and check on the contact sheet |
| Different color on Instagram | untagged file → use the `render.mjs` output (already BT.709); do not re-encode without `-colorspace bt709` |
| Transparency with a dark edge | non-premultiplied alpha → use the kit's `--alpha` (already premultiplies in the blur) |

## 11. Champion brief, anti-"AI look" and the reference library

Basis: analysis of 230 real prompts made in Claude. A 26-word prompt pasted 33 times gave results from 0 to 17 thousand likes: **a vague prompt leaves everything to chance**; the long ones had an 11× higher median. Details in `references/playbook-prompt-motion.md`.

**The 6 blocks of a brief (for you to build before constructing, on a real video request):**
1. **inputs:** what only the user knows (name, logo, accent color, exact text, track), with **defaults** if they skip. Ask once.
2. **direction:** **one concept** in one line + a **bridge element** + a locked look (1 to 2 fonts, ≤ 3 colors + black/white, 1 accent, one camera language) + a **banned list**.
3. **structure:** time in **BPM and bars**; hook in the 1st bar, one technique per bar flowing out of the last, strongest moment in the second-to-last, title at the end, last frame = first frame when it makes sense.
4. **build:** an explicit render method (here: the kit, pure `render(t)`, subframe blur, soundtrack by cues, 60 fps for fluid UI).
5. **gotchas:** known traps (section 10 + those of each template).
6. **start:** show the concept, beat map and 3 to 4 frames before the final render; render one frame per beat and look.

**Banned list (this skill's default, unless the user says otherwise).** Instead of only forbidding, say what to do instead:
- **Glow/neon** → contrast, scale and accent color create the focus.
- **Particle bursts, shockwave rings** → only if born from an element already on screen and going somewhere (motion with no origin is decoration).
- **Crossfade / blur-in** → every scene grows out of the previous one (match cut, morph, a shape that floods and contracts).
- **Camera shake, RGB split, lens flare, grid floor, flashing background** → only on the single impact the idea calls for.
- **Elastic easing on everything** → springs with minimal overshoot; `bouncy` only in playful aesthetics (preset 12).
- **Dead time** → nothing still for > 1 s, unless the viewer needs to read (and then the hold is for reading: 0.3 s + 0.25 s per word).
- **Corner text** (labels, frame markers, decorative timecode) → only information the viewer uses.
- **Generic gradient, stock video or UI, placeholder cards** → the user's real material, the brand's real tokens.
- **`Math.random`** → `M.rng(seed)`. The same frame must come out identical on every render.
- **"Anything that looks like a template"** → close the brief with that standard; it covers effects you did not list.
- **Invented numbers, clients, testimonials and features** → only what the user supplied or what the product really has.

**How to use the reference library (without blowing up the context):**
1. A real video (showreel, launch, promo, UI motion, explainer, typography, 3D)? Read `references/playbook-prompt-motion.md` and the closest template in `references/briefing-templates.md`.
2. For concrete scene ideas, open `references/gallery/00_INDEX.md`, pick the category and read only 2 to 4 prompts similar to the request (the ones at the top have more detail). Or `grep -il "word" references/gallery/*.md`.
3. Gallery prompts were written for a flow similar to the kit's: their `seek(t)` is this kit's `render(t)`; the subframes with `tmix` are `M.blur`; the beat grid is `M.beat`; the numpy music analyzer is `sound.py`/cues. Translate the idea into the kit, **do not copy the prompt's code**.
4. **Every gallery entry has two versions:** the creator's original prompt (often a single sentence) and the **full version**, structured (direction, structure, build, gotchas, first step). To build, start from the full version; its families (showreel, product with research, explainer with narration, silent short, music/lyric, talking-head edit, 3D/game) are summarized in `references/playbook-prompt-motion.md` (section 9) and became templates A to K in `references/briefing-templates.md`.
5. If the user pastes a gallery prompt and asks "make this one": treat it as a brief, fill the missing `inputs` with its defaults, and follow the workflow in section 1.
6. If the idea calls for **real 3D**, **React/Remotion** or **math (Manim)**, see the renderer table in the playbook (section 7) and tell the user about the tool swap before starting.
7. The prompts belong to the creators credited: use them as a reference for structure and ideas, adapt them to the user's brief, and do not republish them as your own.

## Quick `motion.js` API (global object `M`)

- **Frame:** `M.W, M.H, M.S, M.V` (vertical), `M.SQ`, `M.FPS`, `M.pick(h, v, sq)`, `M.safe`, `M.Q` (URL parameters)
- **Time:** `M.seg(t,a,b)`, `M.range(t,a,b,ease)`, `M.remap(t,[[tOut,tSource],...])`, `M.keys(t,[[t,v,ease],...])` (number, array or color), `M.stagger(i,n,each,from)`, `M.staggerGrid(c,r,cols,rows,each,from)`, `M.shots([[name,dur],...],{gap})` → `.name.start/end`, `M.on(t,plane,pad)`, `M.lt(t,plane)`, `M.pulse(t,at,width)`, `M.loop`, `M.pingpong`, `M.step(t,fps)`, `M.frameT(t)`, `M.beat(n)`
- **Easing:** `M.ease.{linear, in/out/inOut + Sine/Quad/Cubic/Quart/Quint/Expo/Circ/Back, outElastic, outBounce, smooth}`, `M.bezier(x1,y1,x2,y2)`, `M.curve.{standard, emphasized, decel, accel, snappy, swift, anticipate, overshoot}`, `M.spring({stiffness,damping,mass,velocity})`, `M.springAt(t,t0,'gentle'|'snappy'|'bouncy'|'wobbly')`, `M.expLerp(a,b,p)`
- **Random/noise:** `M.rng(seed)`, `M.hash(i,j,seed)`, `M.noise2`, `M.noise3`, `M.fbm`, `M.curl`, `M.noiseSeed(n)`
- **Color:** `M.mix(a,b,p)` (OKLab), `M.rgba(hex,a)`, `M.contrast(a,b)`
- **DOM/SVG:** `M.el(tag,attrs,parent,html)` (HTML or SVG automatically), `M.attr`, `M.css(el,{transform:{x,y,z,s,sx,sy,r,rx,ry,skx,px}})`, `M.tf`, `M.show(el,bool)`, `M.split(el,{mask})` → `{lines, words, chars}` (animate `.in`)
- **Text:** `M.scramble`, `M.typewriter` → `{text, caret, end}`, `M.fmt`
- **Stroke/shape:** `M.draw(el,p,from)`, `M.drawRange(el,a,b)`, `M.samplePath(d,n)`, `M.morpher(dA,dB)` → `f(p)`, `M.sampleShape({d}|{text,font},n)`, `M.arc(a,b,p,bend)`, `M.spline(pts,p)`, `M.cursorPath(t,keys)`, `M.cover(r,cx,cy)`
- **Camera:** `M.cam({x,y,zoom,r})` (CSS), `M.camSVG(...)`, `M.shake(t,t0,{amp,dur})`, `M.depth(z)`, `M.drift(t,amp)`
- **Finishing:** `M.grain(parent,{opacity,blend})` → `.update(t)`, `M.vignette(parent,{strength})`, `M.cursor(parent,{size})`
- **Contract:** `M.cue(t,type,{...})`, `M.blur(t0,t1,n)`, `M.boot(render,{dur, init, bpm, poster})`. Browser preview: `scene.html?dev=1` (space = play/pause, arrows = frame by frame, S = safe areas).
